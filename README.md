# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные
Интерфейс товара (IProduct)

interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

Назначение: описывает структуру данных товара, который представлен в каталоге приложения.

Поля: - id: string — уникальный идентификатор товара; - description: string — текстовое описание товара; - image: string — путь к изображению товара; - title: string — название товара; - category: string — категория, к которой относится товар; - price: number | null — цена товара. Может быть null, если цена не указана.

-------------------------------------------------------------------------------------------------------

Интерфейс покупателя (IBuyer)

interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}

Назначение: определяет структуру данных покупателя, которые необходимы при оформлении заказа.

Поля: - payment: TPayment — выбранный покупателем способ оплаты; - email: string — электронная почта покупателя; - phone: string — номер телефона покупателя; - address: string — адрес доставки.

## Модели данных

Класс ProductCatalog (Каталог товаров)

Назначение: отвечает за хранение и управление данными о товарах, доступных в приложении. Хранит общий массив товаров и товар, выбранный для подробного отображения.

Конструктор: Не принимает параметров. Инициализирует внутренние массивы для хранения товаров.

Поля класса: - products: IProduct[] — хранит массив всех товаров; - selectedProduct: IProduct | null — хранит товар, выбранный для подробного отображения.

Методы класса: setProducts(products: IProduct[]) — сохранение массива товаров полученного в параметрах метода. 2. getProducts(): IProduct[] — получение массива товаров из модели. 3. getProductById(id: string): IProduct | undefined — получение одного товара по его id. Возвращает undefined, если товар не найден. 4. setSelectedProduct(product: IProduct) — сохранение товара для подробного отображения. 5. getSelectedProduct(): IProduct | null — получение товара для подробного отображения или null, если ничего не выбрано.

-------------------------------------------------------------------------------------------------------

Класс Cart (Корзина)

Назначение: управляет товарами, которые пользователь добавил в корзину для покупки.

Конструктор: Инициализирует пустой массив для товаров в корзине.

Поле класса: - items: IProduct[] — хранит массив товаров, выбранных покупателем для покупки.

Методы класса: getItems(): IProduct[] — получение массива товаров, которые находятся в корзине. 2. addItem(product: IProduct): void — добавление товара, который был получен в параметре, в массив корзины. 3. removeItem(productId: string): void — удаление товара, полученного в параметре из массива корзины. 4. clear(): void — очистка корзины. 5. getTotalPrice(): number — получение стоимости всех товаров в корзине. 6. getItemCount(): number — получение количества товаров в корзине. 7. hasItem(productId: string): boolean — проверка наличия товара в корзине по его id, полученного в параметр метода.

-------------------------------------------------------------------------------------------------------

Класс Buyer (Покупатель)

Назначение: хранит и управляет данными покупателя, необходимыми для оформления заказа.

Конструктор: Инициализирует все поля объекта значениями по умолчанию (пустыми строками или null`).

Поля класса: - payment: TPayment | null — вид оплаты; - email: string — электронная почта; - phone: string — телефон; - address: string — адрес.

Методы класса: setPayment(payment: TPayment): void — устанавливает способ оплаты. 2. setEmail(email: string): void — сохраняет email покупателя. 3. setPhone(phone: string): void — сохраняет номер телефона. 4. setAddress(address: string): void — сохраняет адрес доставки. 5. getData(): IBuyer — получение всех данных покупателя. 6. clearData(): void — очистка данных покупателя. 7. validate(): { [key: string]: string } — валидация данных.

## Слой коммуникации

Класс ProductApiService

Назначение: выполняет запросы к API сервера «веб‑ларёк». Использует методы класса Api для взаимодействия с сервером.

Конструктор: принимает объект, соответствующий интерфейсу IApi.

Методы: * getProducts(): Promise<{ items: IProduct[] }> — выполняет GET‑запрос на эндпоинт /product/, возвращает объект с массивом товаров. * createOrder(orderData: { buyer: IBuyer; cart: IProduct[] }): Promise<{ total: number }> — выполняет POST‑запрос на эндпоинт /order/, передаёт данные о покупателе и товарах корзины, возвращает объект с суммой заказа.

## Слой Представления (View)

Отвечает исключительно за отображение данных и обработку пользовательских взаимодействий. Не содержит бизнес-логики и не хранит данные приложения (все данные хранятся только в Моделях). 

Важные архитектурные особенности
Компоненты представления не клонируют шаблоны самостоятельно. Они получают уже готовый корневой `HTMLElement` (склонированный Презентером с помощью утилиты `cloneTemplate`) через конструктор.
Для избавления от хранения данных (например, `id` товара) в представлении, карточки принимают колбэк-функции при инициализации, а не экземпляр `EventEmitter`.
Все DOM-элементы кэшируются в полях класса в конструкторе (через `ensureElement` или `querySelector`). Повторный поиск элементов внутри сеттеров запрещён.
Для обновления состояния используется единый метод `render(data)`, который принимает объект с данными и вызывает нужные сеттеры.

Основные компоненты
HeaderView — отображение иконки корзины со счётчиком. Генерирует событие `basket:open`.
GalleryView — отображение списка товаров в каталоге (принимает массив готовых `HTMLElement`).
ModalView — управление отображением модальных окон (открытие/закрытие, очистка контента).
BasketView — отображение списка товаров в корзине и общей суммы. Принимает состояние кнопки "Оформить" через сеттер `buttonDisabled`.

Классы для карточки товара
Card (родительский) — общий функционал для всех карточек (рендеринг названия и цены).
CatalogCard (дочерний) — карточка для каталога. Принимает колбэк `onSelect`. При клике вызывает его, что приводит к генерации события `card:select` на уровне Презентера. Не хранит `id` товара.
DetailedCard (дочерний) — расширенная карточка для модального окна превью. Принимает `EventEmitter` и `id` товара. Генерирует событие `card:add` при клике на кнопку действия.
BasketCard (дочерний) — карточка товара внутри корзины. Принимает колбэк `onRemove`. При клике на кнопку удаления вызывает его, что приводит к генерации события `basket:remove` на уровне Презентера.

Классы для форм
BasicForm (родительский) — базовый функционал для форм. Отслеживает событие `input` и генерирует события вида `fieldName:change`. Содержит сеттер `valid` (управляет свойством `disabled` кнопки отправки) и сеттер `errors` (вывод текста ошибки). Не хранит внутреннее состояние валидации (геттер `valid` удалён).
OrderForm (дочерний) — форма выбора способа оплаты и ввода адреса. Кэширует кнопки оплаты в конструкторе. Генерирует события `payment:change` и `order:submit`.
ContactsForm (дочерний) — форма ввода email и телефона. Генерирует событие `contacts:submit`.
SuccessView — окно успешного оформления заказа. Генерирует событие `success:close`.

## Логика Презентера

Презентер (`main.ts`) связывает модели и представления через шину событий (`EventEmitter`), выступая единственным источником логики связывания.

Основные сценарии

Загрузка каталога:
   `apiService` получает данные, `productsModel` сохраняет их и генерирует `products:changed`. Презентер создаёт массив экземпляров `CatalogCard` (передавая колбэки) и вызывает у каждого `.render({...})`, после чего передаёт массив в `galleryView.items`.

Просмотр и добавление товара в корзину:
   Событие `card:select` от `CatalogCard`. Презентер находит товар по ID и вызывает `productsModel.setSelectedProduct()`. Модель генерирует `product:changed`. В ответ на это Презентер создаёт `DetailedCard`, вычисляет текст и состояние кнопки (проверяя `cartModel.hasItem()` и `price === null`) и вызывает `.render({...})` с полными данными.
   Событие `card:add` от `DetailedCard`. Презентер проверяет наличие товара в корзине: если есть — вызывает `cartModel.removeItem()`, если нет — `cartModel.addItem()`.

Управление корзиной:
   Экземпляр `BasketView` создаётся **один раз** при инициализации приложения. 
   При изменении корзины модель генерирует `basket:changed`. В этом обработчике Презентер:
   Обновляет `counter` в `HeaderView`.
   Создаёт массив `BasketCard` (через колбэки) и вызывает `basketView.render({ items, total, buttonDisabled })`.
   Событие `basket:open` просто открывает модальное окно с уже актуальным контентом: `modalView.content = basketView.render()`.
   Событие `basket:remove` только вызывает `cartModel.removeItem()`, а перерисовка происходит автоматически благодаря `basket:changed`.

Оформление заказа (Шаг 1 и 2):
   Экземпляры `OrderForm` и `ContactsForm` создаются **один раз** при инициализации.
   При вводе данных (события `address:change`, `payment:change`, `email:change`, `phone:change`) Презентер вызывает соответствующие сеттеры модели `buyerModel` (например, `buyerModel.setAddress()`). 
   Модель при изменении генерирует событие `buyer:changed`. В ответ на это Презентер вызывает `buyerModel.validate()`, получает объект ошибок и обновляет формы через единый вызов `.render({ valid, errors, address, payment })`, передавая актуальные данные. Проверка валидации полностью делегирована модели.

Завершение заказа:
   Событие `contacts:submit`. Презентер собирает итоговый объект заказа из данных моделей (`buyerModel` и `cartModel`) и вызывает `apiService.sendOrder(orderData)`. 
   При успешном ответе сервера Презентер вызывает `cartModel.clear()` и `buyerModel.clear()`, после чего открывает `SuccessView`, подставляя итоговую сумму из ответа сервера (`result.total`).
